# 작은 CNN으로 세 가지 소리 분류하기

이 프로그램은 **공작기계음·금속 충돌음·비명 중 하나를 고르는 학습용 프로그램**입니다.
음원과 JSON 정답을 읽고, 소리를 그림으로 바꿔 작은 CNN을 훈련합니다.
학습 중 내부 검증을 하고, 저장한 모델을 다시 불러와 검증·최종 테스트 자료 전체를 평가합니다.

코드 파일은 세 개이고, 계산 방법을 쉬운 한국어 주석으로 설명했습니다.
작업 맥락 판단, 위험 점수, 디지털 트윈, 웹 화면, 실시간 마이크, 복합음 분류는 없습니다.
직접 실행한 성적과 검수 내용은 이 문서 끝과 `results/verification.json`, `NOTES.md`에 기록합니다.

## 4. 소리는 어떻게 그림이 되나요?

`MP3 → 정답 구간 창 → 모노 → 22,050 Hz → 90,316샘플 → 진폭 정규화 → Log-Mel`

JSON에서 가장 긴 정답 구간을 고릅니다. 약 4.096초보다 길면 중앙 창을 자르고,
짧으면 해당 구간을 읽어 뒤에 0을 채웁니다. 비어 있는 자료나 읽기 실패를 무음으로 바꾸지 않습니다.
JSON 끝 시간이 파일 길이를 넘는 경우 소수점 반올림 수준의 0.05초만 허용하며 실제 파일 끝에서 자릅니다.

스테레오는 채널 평균으로 모노가 됩니다. 재샘플링은 소리의 시간 길이를 유지하면서
1초를 표현하는 숫자 수를 바꿉니다. 정규화는 파형의 최대 절댓값을 약 1로 맞추는 것이고,
잡음 제거·실제 소음 크기 측정·데시벨 계산이 아닙니다.

Log-Mel 그림은 시간에 따라 어느 주파수 영역이 강한지 나타냅니다.
0에 로그를 취할 수 없어 최소값 `1e-6`을 두고 자연로그를 계산합니다.
증강, 잡음 제거, 캐시, 별도 데이터 읽기 프로세스는 사용하지 않습니다.

실제 입력 모양은 파형 `[90316]`, 소리 그림 `[1, 128, 353]`,
배치 입력 `[8, 1, 128, 353]`, 출력 `[8, 3]`입니다. 마지막 배치는 8보다 작을 수 있습니다.

### 바꿔 볼 파라미터

- `dataset.py / SETTINGS / sample_rate=22050`: 1초당 숫자 수이며 단위는 Hz입니다.
- `num_samples=90316`: 창의 샘플 수입니다. 주파수와 함께 창의 시간 길이를 결정합니다.
- `n_fft=2048`: 주파수 분석에 한 번에 쓰는 샘플 수입니다.
- `hop_length=256`: 분석 창 사이 이동 간격입니다. 작게 하면 시간 방향 칸과 계산량이 늘어납니다.
- `n_mels=128`: 그림 세로 칸 수입니다. 주파수를 사람의 청각 특성을 참고한 영역으로 묶습니다.
- `f_min=10.0`: Mel 영역의 최저 주파수이며 단위는 Hz입니다.
- `main.py`의 `--batch-size`: 한 번에 학습하는 자료 수입니다. 메모리 사용량에도 영향을 줍니다.
- `--epochs`: 학습 목록을 도는 횟수입니다. 많이 돌리면 무조건 좋은 것은 아닙니다.
- `--learning-rate`: Adam이 가중치를 고치는 크기를 조절합니다. 고정된 수정 비율을 뜻하지 않습니다.

전처리 값을 바꾸면 **새로 훈련**하세요. 평가는 저장 모델의 설정을 읽으므로,
코드의 상수만 바꾸어 예전 모델을 다른 설정으로 평가하지 않습니다.

## 5. 작은 CNN과 학습

`Conv(1→16, 3×3) → ReLU → MaxPool(2) → Conv(16→32, 3×3) → ReLU → MaxPool(2)`

`→ AdaptiveAvgPool(1×1) → Flatten → Linear(32→3)`

학습할 숫자는 총 **4,899개**입니다. 각 합성곱 층이 주변 무늬를 계산하고,
ReLU가 음수를 0으로 바꾸며, MaxPool이 주변 2×2에서 가장 큰 값을 남깁니다.
마지막 평균 풀링은 특징 지도마다 평균 숫자 하나를 남겨 출력층 크기를 단순하게 맞춥니다.
기존 ImageNet이나 음향 가중치는 불러오지 않습니다.

학습은 `zero_grad → model → loss → backward → optimizer.step` 순서입니다.
`backward()`는 수정 방향을 계산하고, `step()`이 가중치를 실제 수정합니다.
손실 함수는 CrossEntropyLoss, 수정 방법은 Adam입니다.
CrossEntropyLoss에는 softmax를 적용하지 않은 원시 점수를 전달합니다.

학습 정확도는 각 배치의 **수정 직전 예측**을 모은 값입니다.
내부 검증은 에포크가 끝난 모델로 계산합니다. 두 숫자의 계산 조건은 다릅니다.
`train()`·`eval()`은 모드 전환이고, 실제 학습 여부는 역전파와 optimizer 실행 여부로 구분합니다.

`results/splits.json`은 최초 조사 목록입니다. 각 학습 결과 폴더에도 분할 사본을 저장합니다.

학습 폴더는 한국 시간 기준 `results/train_연월일_시분/` 형식으로 만듭니다.
예: `train_20261106_1430`. 같은 분에 다시 실행하면 기존 폴더를 보호하기 위해 안내 후 중단하므로 다음 분에 실행하세요.

- `splits.json`: 이번에 사용한 고정 자료 목록과 제외 기록.
- `history.json`: 에포크별 학습 손실·학습 정확도·내부 검증 성적.
- `best.pt`: 내부 검증 Macro F1이 가장 좋았던 모델, 클래스 순서, 전처리 설정, 학습 조건.
- `training_result.json`: 실제 에포크·가중치 수정 횟수·시간·최고 내부 검증 성적.

- `evaluation_val_시각.json/png`, `evaluation_test_시각.json/png`: 재로딩 평가와 혼동행렬.
- `failure.json`: 학습 반복 중 실패·중단했을 때의 오류와 진행 횟수. 자동 재개 기능은 없습니다.

완료한 최신 실행 폴더는 `results/latest_run.txt`에 기록합니다.
저장 가중치는 CPU 형식이라 MPS로 학습한 뒤 CPU에서도 불러올 수 있습니다.

## 7. 공식 예제 및 기존 mac_run.py와 다른 점

신호처리의 샘플링 주파수·창 길이·FFT·hop·Mel·자연로그 설정은 공식
`model/config.yaml`, `model/common_utils.py`를 참고했습니다.
원본 구형 Flash/Lightning/CUDA 실행부를 복사하지 않았습니다.
작은 CNN·분할·학습·평가·CLI는 이번 프로그램용으로 작성했습니다.

공식 MobileNetV2나 기존 Mac용 전이학습 결과를 수치적으로 재현한 실험이 아닙니다.
기존 `mac_run.py`는 세 칸 독립 정답과 BCE를 쓰지만, 이번에는 정수 정답 하나와
CrossEntropyLoss를 쓰는 **단일 정답 3클래스 분류**입니다. 모델과 가중치는 서로 교환할 수 없습니다.
이전 학습의 F1 수치를 이 모델의 성적으로 가져오지 않습니다.

## 8. 결과를 해석할 때

정확도는 전체 중 맞힌 비율입니다. 정밀도는 해당 소리로 예측한 것 중 맞힌 비율,
재현율은 실제 해당 소리 중 찾아낸 비율입니다. F1은 이 두 성질을 함께 보는 점수입니다.
Macro F1은 세 종류 F1의 단순 평균입니다. 분모가 0인 종류의 점수는 0으로 둡니다.

혼동행렬은 **행=실제 정답, 열=예측**입니다. 비명 행에서 다른 종류 열로 간 수가 비명을 놓친 수입니다.
비명 자료가 적어 정확도만 보면 성능을 과대평가할 수 있습니다. 클래스별 F1·FN을 함께 보세요.

모든 입력을 세 종류 중 하나로 고르므로 무음이나 다른 소리도 셋 중 하나로 나올 수 있습니다.
정답 시간 구간을 알고 고른 창에 대한 평가이며 연속 현장 탐지 성능은 미검증입니다.
실제 현장 시험, 복합음, 낯선 소리 거부, 잡음 강건성, 장시간 운영은 이번 범위에 없습니다.
시드 42는 비교 조건을 맞추지만 장치별 완전히 같은 소수점 결과를 보장하지는 않습니다.
